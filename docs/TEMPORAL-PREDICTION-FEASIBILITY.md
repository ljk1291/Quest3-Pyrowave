# Offline PyroWave temporal-prediction feasibility

This is an offline model, not live codec code or a proposal to promote a default. It uses the actual pinned PyroWave encoder and decoder, CDF 9/7, explicit RDO 24 and a strict 1,388,888-byte payload cap per frame (floor of 1000 Mbps / 90 / 8). The first frame is intra; later frames encode `source - prediction(previous decoded reconstruction) + 128` in the existing full-range 8-bit C420 format. Reconstruction adds the decoded residual to the same prediction and subtracts 128. Both residual and reconstructed output clipping are counted per plane and frame.

The native sequence uses the previous decoded image unchanged. The synthetic sequence shifts each eye independently by the known integer crop displacement, with exact half-size chroma shifts. Newly exposed pixels predict neutral 128. This is a known-motion crop model, not a measured head turn, a game motion estimator or a depth-aware reprojection. Source geometry, frame identity, motion manifest, byte caps, native logs, builds and clean finite PC lease closure are gates. GPU completion records are retained as provenance; contention policy makes timings unqualified. No fresh-submission or optical rate is inferred.

## What this model can establish

A comparison can establish quality and clipping at the same payload cap on this corpus. It cannot establish Quest speed, compatibility with the ordinary live intra protocol, or robustness to packet loss. The current model starts a fresh encoder and decoder process for each frame. Process startup time is not a prospective decoder latency estimate. Native intra comparison is reused; the synthetic unfoveated intra control is new because its input differs.

Two fresh first-frame encodes and the retained batched first-frame payload have different raw hashes but the same payload length. Decoding all three produces exactly identical Y, Cb and Cr samples. Source review points to unused high bits in partially filled sign bytes (`block_packing.comp::flush_sign_plane`) that are serialized but never consumed by dequantization. The experiment retains the raw hashes and requires first-frame decoded equality; it does not claim byte-deterministic encoding. This is a first-frame reproducibility check, not a proof for every possible image or backend.

## Native-sequence result, 2026-10-05

All 90 frames completed under a clean PC-only quality lease. Fence edge PSNR-Y is 30.558714 dB, temporal residual p99 is 49, and whole-crop HVS is 35.683889 dB. The retained intra 9/7 / RDO 24 / 1000 comparator is 39.933228 dB, p99 12 and HVS 43.008816 dB. The unchanged-previous-frame model therefore loses 9.374514 dB on the fence and 7.324927 dB on HVS on this corpus.

Across frames 2–90 and all three planes, 0.24665% of residual samples clip outside the representable signed interval; 0.30259% of reconstructed samples clip at the output limits. Small global fractions do not bound error on thin fence edges. The native capture includes camera/scene changes, so it is not a verified still-head sequence. This result rejects the specified unwarped, 8-bit residual model for these frames; it does not establish that a wider signed residual or a correctly warped predictor cannot work. Those would be separate hypotheses.

## Synthetic known-motion result, 2026-10-05

All 90 frames also completed with the previous decoded reconstruction shifted by the known crop displacement. Fence edge PSNR-Y is 30.515085 dB, temporal residual p99 is 49, and whole-crop HVS is 35.293644 dB. The new intra control on exactly the same synthetic sequence is 40.162095 dB, p99 12 and HVS 42.879844 dB. The shifted residual model loses 9.647010 dB on the fence and 7.586200 dB on HVS. Residual clipping is 0.25696% and reconstruction clipping is 0.32267% across frames 2–90 and all planes.

These results reject both specified 8-bit residual models at this byte cap. Integer motion compensation alone did not rescue them. Keep this finding separate from the quality of ordinary intra PyroWave, and do not treat the model's per-process completion times as a live latency measurement. The synthetic source moves both eyes consistently by 16 pixels per frame, ping-ponging within the available crop margin; its nominal 60 degrees/s interpretation assumes 24 pixels/degree.

## Live design issues

- **Rotation warping:** For each eye, map destination rays through the delta between the reference and current head rotations, then project into the reference eye using its actual asymmetric tangent frustum, crop and projection matrices. In pinhole notation the image mapping derives from `K_reference * R_delta * inverse(K_current)`; invert it for destination-to-source sampling. Define top-down coordinates, chroma phase, borders and interpolation exactly. Translation, independently moving objects and disocclusion require residuals; a rotation-only warp cannot predict them. A real positional warp requires depth and is a separate hypothesis.
- **Reference agreement:** The PC must predict from exactly the same decoded samples the Quest retains. Different floating-point wavelet operations, intermediate precision, rounding, colour conversion or warp filtering on NVIDIA and Adreno can make references drift. A PC-only closed loop does not prove cross-device parity. Require decoded-plane/reference hashes across backends, a specified deterministic reconstruction format, and explicit reset identities. An 8-bit residual offset cannot represent every difference in [-255,255]; measured clipping is a limitation, not a quality improvement.
- **Refresh and recovery:** Introduce a versioned inter-frame protocol with reference/frame IDs, sequence/refresh markers and explicit invalidation after missing/corrupt references. Use periodic intra refresh and immediate refresh after reconnect or reference loss. Never predict from an unverified stale frame. Refresh consumes bitrate; the fixed-cap model does not hide refresh costs or claim that all frames have the same quality.
- **Quest cost:** The client needs a retained reference image, warp/read pass, residual addition/clipping and synchronization before presentation. Fusing warp/add with the final wavelet or colour conversion may reduce passes, but adds sampling, memory traffic and state lifetime hazards. No Quest timing was measured tonight. Extra GPU work could outweigh byte savings on the current decoder; direct YUV/final-stage fusion should be assessed on the faster allocation configuration first.

The PyroWave bitstream remains an ordinary image stream only for the residual images themselves. A stock intra client would display those residuals, not the reconstructed scene. This model therefore provides no compatibility claim for an unchanged ALVR client. Preserve PyroWave/Granite MIT attribution and review licences before adapting additional implementations.
